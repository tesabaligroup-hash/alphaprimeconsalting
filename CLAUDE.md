# Alpha Prime — Telegram Mini App

Владелец: Tesa (Alpha Prime Consulting, Бали). Общение и тексты интерфейса — на русском.

## Что это
Личный кабинет клиента + партнёрская программа в Telegram. ТЗ: модули 3 и 4 «ТЗ Alpha Prime v2.1» + «ТЗ Партнёрская программа» (11.11.2026).
Макеты согласованы на канвасе Design «Alpha Prime — Telegram-приложение (экраны)». Стиль — белый/золотой:
ink #1C1A16, gold #C9A24B, gold-ink #7A5C17, cream #FBF7EC; заголовки Cormorant Garamond, текст и все цифры — Manrope.

## Стек
- `backend/` — FastAPI + SQLAlchemy 2 (PostgreSQL, в тестах SQLite), aiogram 3 (бот в `app/worker.py`), Jinja-админка `/admin`.
- `frontend/` — React + Vite + TS, Mini App. Сборка кладётся в образ и отдаётся FastAPI.
- Kommo: `app/kommo/real.py` (API v4), `mock.py` (тестовые данные), `mapping.py` (поля/этапы — пометки ПРОВЕРИТЬ).
- Выкладка: push в `main` → GitHub Actions (тесты + сборка) → ssh на сервер → `docker compose up -d --build`.

## Правила, которые нельзя нарушать
- Партнёр видит только имя/ник друга, статус и свою сумму. Никаких услуг, цен, маржи, процентов, паспортных данных.
- Вознаграждение — только за друзей, которые заказали И оплатили услугу, а к выплате — только после того, как услуга выполнена (результат выдан). Во всех текстах партнёру так и писать. Уровней максимум 2.
- Выплаты (с 15.11.2026) — фиксированные суммы из таблицы тарифов, не проценты: колонка «партнер» — 1-й уровень (кто привёл клиента, одинаково для всех), «партнер 2ур» — 2-й уровень (кто привёл к нам партнёра-канал: главу кафе, спортзала), = 20% от 1-го. Клиент партнёра платит «Цену для парт.»; white label — цена для перепродажи под своим брендом. Тарифы: `app/tariffs.py`, расчёт: `app/partner_rules.py`, эталон: `tests/data/tariffs_expected.json`. Редкие услуги без сумм в таблице — партнёрка не выплачивается (начисления нет).
- Рассылка партнёрам после изменения программы: `python -m app.notify_partners` (проверка) / `--send`.
- Кодовое слово: ≥6 символов, буквы/цифры, не общее слово (стоп-лист в коде + в админке), уникальное. У партнёра может быть до 10 слов (`partner_codewords`, например отдельное для спортзала); первое — основное (`Partner.codeword`). Слова не удаляются; менять основное — только менеджер. Поиск партнёра по слову — только через `partner_by_codeword`.
- QR и ссылки партнёра (с 16.11.2026) ведут прямо в чат менеджеров — WhatsApp или Telegram @alpha_prime_id (константа в `app/links.py`; WhatsApp — COMPANY_WHATSAPP, +62 815-1984-5777) с текстом «Я от СЛОВО», не в бота. Кнопка «Скачать QR-код» — PNG для печати (`app/qr.py`, временная ссылка `/api/qr/{token}`).
- Этапы клиента (12.11.2026 — 3 шага): Оплата → Подача в иммиграцию (у не-визовых услуг «В работе») → Готово.
- Поле «Партнёр» приложение заполняет само для закреплённых клиентов (12 мес.), «Нет»/«Другое» от менеджера не трогает. Бот в группе менеджеров: /kod СЛОВО, /proverka; по понедельникам — список недозаполненных сделок.
- Виджеты Telegram (`app/widgets.py`): /visa, /events, /partner в личном чате с ботом; обновляются раз в час; «Хочу пойти» → заявка как у новости. Партнёрский виджет — без услуг и цен.
- «Мои визы» (16.11.2026): любой пользователь бота (даже не наш клиент) вписывает визу и дату окончания (`UserVisa`, экран `MyVisas`). Бот раз в день после 10:00 напоминает за 20/15/7 дней (и нашим клиентам по датам из Kommo) с кнопкой «Продлить с Alpha Prime» → сделка в Kommo + группа менеджеров; за 20 дней — сигнал менеджерам. Админка → «Визы». Логика: `app/services/visas.py`.
- Автозаявка (обновлено 17.11.2026 вечером): строки на лист «Заявки авто» в ТОМ ЖЕ порядке колонок, что «Производство» (A…Z) + AA «ID сделки», «Проверить (ИИ)», «Сделка в Kommo» — Tesa сама копирует строку в «Производство». Семья — строка на каждого человека × каждую услугу. ПАРТНЕР — кодовое слово партнёра. «Закрепили» — поле сделки «Закрепили» или последнее примечание со словом «закреп…» → в «Комментарии» и в сообщение «====New Client====» в группу менеджеров (формат, как раньше писали вручную). Документы — в папку клиента из поля контакта «Документы», если есть.
- Партнёры при TABLE_SYNC_PARTNERS: гибрид — до появления строки в таблице начисление «ожидается» по Kommo (статусы выше «в работе» обрезаются), после — по таблице (по ID сделки в колонке AA или тому же другу у того же партнёра).
- Автозаявка в производство (17.11.2026, `app/services/intake.py`, включается `INTAKE_ENABLED=true`): сделка встала на «Оплата получена» → ИИ (`app/ai_docs.py`, ANTHROPIC_API_KEY) читает файлы сделки → строка на лист «Заявки авто» таблицы производства + папка на Диске (Apps Script `deploy/intake-apps-script.gs`, INTAKE_SCRIPT_URL/SECRET) → пустые ФИО/гражданство/паспорт до в контакт → чего не хватает — в группу менеджеров. «Услуга готова» → готовую визу/ITK прикладывает МЕНЕДЖЕР; ИИ сверяет имя, отмечает в поле «Документы клиенту» (появляется в приложении), пишет «Виза до»/«ITK до». Чужое имя — клиенту не показываем, сигнал менеджерам. Только сделки, попавшие на этап после включения. Ручная проверка: `python -m app.intake --lead ID [--ready] [--apply]`.
- Таблица производства — источник правды о выполненных услугах (17.11.2026, `app/services/table_sync.py`, включается `TABLE_SYNC=true`): сделки в Kommo НЕ закрываются. Лист «Производство», колонка N (статус): «Партнерку выплатить» → начисление «К выплате» + услуга «Готово»; «ГОТОВО» → «Выплачено»; «СТОП» → отменено. Одна строка = одна услуга; сумма — колонка X «Доля партнеров», иначе тариф. Партнёр из колонки E → по имени/кодовому слову/нику или через лист «Список партнеров» (t.me/ник, телефон WA). Начисления по сделкам Kommo в этом режиме не считаются (удаляются). Даты виз/ITK — листы «Продления и доступы» и «Новые продления» (A виза, B клиент, F статус, H дата) → «Виза до»/«ITK до» в контакт. Раз в сутки после 03:00 (Бали). Начисления партнёрам по таблице — только при `TABLE_SYNC_PARTNERS=true` (иначе считаются по Kommo, как раньше). `TABLE_MOVE_STAGES=true` — выполненные сделки сами переходят в «Услуга готова» (только если сделка одна и встала на этап не позже строки таблицы). Читает тот же Apps Script (doGet) — логины/пароли не отдаются. Проверка: `python -m app.table_sync [--apply] [--move]`. Скрипт ставится с аккаунта-владельца таблицы (baliprimeconsalting@gmail.com).
- Документы клиента (17.11.2026, `app/services/drive_docs.py`, включается `DRIVE_DOCS=true`): у контакта Kommo поле «Документы» — ссылка на папку Google Диска. Раз в сутки (после 04:00 Бали) Apps Script (action=list/file) отдаёт файлы; ИИ (сначала `AI_MODEL` claude-haiku-5-5, если не разобрал — `AI_MODEL_STRONG`) определяет визу/ITK и имя; на имя ЭТОГО контакта — копия в `DOCS_DIR` (/data/docs, том client_docs, НЕ публичный) + `ClientDocument`; чужие/паспорта/черновики — не показываем. Прочитанное кэшируется (`DriveFileRead`), дубли (PDF+фото, та же дата) не сохраняются. Приложение: «Документы» → «Активные» (срок не прошёл) / «Архив», по людям: сам + контакты его сделок (семья). Файл — только по временной ссылке `/api/files/…` (lead_id=0, uuid=d<id>). Поле «Документы клиенту» в Kommo не нужно. Проверка: `python -m app.drive_docs --contact ID [--apply]`.
- «Смотреть как клиент» (20.11.2026): сотрудники (`STAFF_USERNAMES`, по умолчанию aplebedev, souzemlivod) видят вкладку «Админ» → поиск по телефону/@нику/имени (пользователи бота + контакты Kommo) → приложение с заголовком `X-View-As: u<id>|c<contact_id>` открывается как у клиента. Только просмотр: любые изменения → 403, кроме QR/ссылок партнёра и открытия документов. Каждый просмотр — в AuditLog (action=view_as). Контакт без аккаунта — временный User(id=0), в базу не пишется.
- «Мои файлы» (20.11.2026): во вкладке «Документы» клиент сам хранит паспорт, права, страховку и т.п. (`UserFile`, `/api/my-files`), до 40 файлов по 10 МБ, PDF/фото (тип по содержимому), в `DOCS_DIR/users/<id>` — видит только владелец (в режиме «Смотреть как клиент» — только список, открыть нельзя). «Действует до» → «Скоро истекает» за 60 дней.
- Тестовый режим (временно): карточка «Нашли ошибку?» на главной и в профиле → `/api/feedback` → группа менеджеров. Убрать после запуска.
- Почта (Яндекс 360, IMAP): `python -m app.mail_scan` — только чтение (MAIL_USER/MAIL_PASSWORD — пароль приложения).
- В каталоге нет школьных и пенсионных KITAS (`in_catalog=False`).
- Секреты только в `.env` на сервере, не в репозитории.
